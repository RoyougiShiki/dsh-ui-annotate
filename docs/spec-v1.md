# 规格：dsh-ui-annotate 第一期

> 状态：**ready-for-agent**　写于 2026-11-13

## Problem Statement

我要在**已经登录**的网页上调 UI，但说不清楚要改什么。截图看不出是哪个元素；「把按钮放大一点」模型不知道放大到多少；「把这张卡挪到那边」模型不知道「那边」在哪。

现有插件都不行：自己开无头浏览器的拿不到我的登录态，侧栏代理的也拿不到，还都得我自己记住一个端口地址。

## Solution

装一个浏览器扩展。在任意标签页点它的图标，页面浮出标注条。我点元素、拖手柄改尺寸、拖着移动、或者转个角度，然后写一句「要改成什么」。扩展把「哪个元素 + 从多少到多少 + 我的话」拼成一段结构化 markdown，塞进 dsh 的输入框。我自己看一眼，再按发送。

## User Stories

1. 作为一个在后台系统上工作的用户，我想在已登录的页面上点一个元素就拿到它的定位信息，这样我不用手写选择器。
2. 作为一个说不清「放大到多少」的用户，我想拖手柄改尺寸并看到实时预览，这样我能直接调到位而不是猜数字。
3. 作为一个想把卡片挪位置的用户，我想拖动元素并看到它落在哪个邻居之前/之后，这样模型不用猜「那边」是哪边。
4. 作为一个要调角度的人，我想旋转元素并读到角度数值。
5. 作为一个希望对齐的人，我想拖到接近邻居边缘时自动吸住并看到辅助线，这样我不用手动对齐。
6. 作为一个要一次说清多处的用户，我想连续标注多个元素、最后一次性送进输入框，而不是发十几条消息。
7. 作为一个担心留下痕迹的用户，我想预览结束后页面恢复原样，这样我不会改坏凭直觉点过的页面。
8. 作为一个要复查内容的用户，我想在发送前看到输入框里的文字，这样我能改措辞。
9. 作为一个刚装插件的人，我想在 dsh 的设置页里看到「怎么装扩展」的三步指引，这样我不用上网搜。
10. 作为一个扩展没装的人，我想在设置页里看到明确的原因说明，这样我知道为什么点了没反应。
11. 作为一个没有 dsh 页面打开的人，我想扩展仍然能在当前标签页工作（并提示先打开 dsh），这样我不会以为它坏了。
12. 作为一个看重隐私的人，我不想扩展在我没点它的时候在别的网站上跑任何脚本。
13. 作为一个中文用户，我想界面文案是中文（跟随 dsh 语言设置）。
14. 作为一个模型，我想收到的是有选择器、可见文本、旧值→新值的结构化文本，这样我能直接定位到代码。

## Implementation Decisions

### 组成

两个包，同一个仓库：

- `packages/extension/` —— MV3 扩展。它是唯一能碰到真实登录态的东西。
- `packages/dsh-plugin/` —— dsh 客户端小插件。提供设置页安装引导；宿主页侧的草稿写入由扩展负责。

### 扩展的三个部分

1. **背景（service worker）** —— 只管状态：当前标签页 ID、这一批条目、是否在标注模式。
2. **目标页内容脚本** —— 标注器本体。`activeTab` 按需注入（用户点工具栏图标触发）。负责取元素、套手柄、预览、还原、生成条目。
3. **宿主页内容脚本** —— manifest `matches` 匹配 `http://127.0.0.1:3081/*`，常驻。负责接收条目并写进草稿。

### 目标页 → 宿主页的传输

不经过网络，不用端口、不用 token。背景脚本给宿主页发消息，宿主页内容脚本执行填充。**已实测**：manifest `matches` + `host_permissions` 就能注入宿主页；`window.postMessage` 与 `chrome.runtime` 都能通。

### 手势

用 `subjx@2.0.1`（见 [ADR-0003](../adr/0003-subjx-for-gestures.md)）：

`subjx(el).drag({ resizable: true, rotatable: true, proportions: false })`

- **必须同时注入 `dist/style/subjx.css`**，否则手柄是 0×0 元素、鼠标点不到（实测踩过）。
- 事件：`drag` / `resize` / `rotate` / `dragEnd` / `resizeEnd` / `rotateEnd`。
- 读数值：`getDimensions()` 返回 `{ x, y, width, height, rotation }`。

### 吸附（自己补）

`subjx` 只有 `applyAlignment('tr')`（按一下对齐到某方位），**没有拖动时的自动吸附线**。第一期自己实现：

- 拖动中，取目标元素与同容器内兄弟元素的 `getBoundingClientRect()`；
- 边缘差在阈值内（建议 6 px）时，把 `transform` 的位移修正到贴合值；
- 同时画一条 1px 辅助线（自己的 overlay，不进页面结构）。

用户已确认：**「有吸附功能就行，没有说一定要什么样的交互方式，只要自然合理都可以接受。」**

### 预览与还原

拖动时实时改 `style`（用户要看效果）；结束（`dragEnd` / `resizeEnd` / `rotateEnd`）时记下「旧值 → 新值」，然后把 `style` 还原。

> 注意：这是第一期唯一允许「改目标页」的地方，且必须还原。

### 条目与序列化

每条条目的形状（内部结构，不是传输格式）：

`{ selector, tag, text, rectBefore?, rectAfter?, rotationBefore?, rotationAfter?, note }`

序列化成结构化 markdown（见 [ADR-0004](../adr/0004-markdown-payload.md)）。多条按点选顺序拼接，一次性写进草稿。

### 草稿写入

宿主页侧用 `document.execCommand('insertText', false, markdown)`（见 [ADR-0002](../adr/0002-send-into-draft-not-send-message.md)）。**已实测在 ISOLATED world 里可用**。**不发送**。

### 入口与设置页

- 唯一入口：**扩展工具栏图标**。点击后在**当前标签页**开启标注。
- dsh 插件只提供一个 `'settings.section'` 页，内容只有一件事：**怎么装扩展**（三步 + 当前扩展目录路径 + 一键复制）。
- **不做斜杠命令**。用户：「斜杠命令不明白是做什么的」。

### 权限

- `activeTab` + `scripting` —— 用户点图标才有当前页权限。
- `host_permissions` 只含 `http://127.0.0.1:3081/*` —— 只为把条目送回 dsh。
- **不申请** `<all_urls>`。

## Testing Decisions

好测试的标准：只测**外部行为**，不测实现细节。

- **可单测的纯函数**：条目序列化（给定条目 → 期望 markdown）、选择器生成（给定 DOM 片段 → 期望选择器）、吸附计算（给定两个 rect + 阈值 → 期望修正量）。这些不需要浏览器。
- **需要真实浏览器的**：标注器能否注入、手柄能否拖、数值能否读到、草稿能否写入。这些用 `ego-browser.exe` 脚本做冒烟验证，不入单元测试套件。
- **先例**：本机没有现成的同类测试；`subjx` 与 `VisBug` 的验证脚本可作为写法参考（临时 stub 页 + 真实鼠标事件）。

## Out of Scope

- 不直接发送消息（只填草稿）。
- 不做斜杠命令。
- 不放侧栏。
- 不做「改文字 / 改颜色 / 改间距 / 换图」（VisBug 有，但第一期不做）。
- 不跨页累积（刷新或跳转即清空当前批）。
- 不做扩展的静默安装（Chromium 不允许）。
- 不接管 `dsh-annotated-browser`（它继续按自己的方式存在）。
