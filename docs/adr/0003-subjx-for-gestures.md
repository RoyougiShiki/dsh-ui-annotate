# ADR-0003：手势用 subjx，不自写拖拽逻辑

- **Status**: accepted
- **Date**: 2026-11-13

## 背景

用户要的不只是「点一个元素写一句话」，还有**拖动、缩放、旋转、吸附**（原话：改尺寸、移动「只靠文字很难精确说明」）。用户明确说「如果可以不自己维护是最好的」「关键取决维护成本，依赖和复杂度」。

候选实测（真机，ego + CDP 真实鼠标，探针在 `%TEMP%\\dsh-ui-annotate-probe\\libprobe\\`）：

| 库 | min.js / gzip | 最后发布 | 实测结果 |
|---|---|---|---|
| `subjx` | 104 KB / **34 KB** | **2026-11-12** | 拖 / 缩放 / 旋转 **全部读到值** |
| `interactjs` | 96 KB / 28 KB | 2026-08-01 | 缩放可用，拖动 **0 事件** |
| `moveable` | 240 KB / 76 KB | 2023-12-03 | 构造成功，真实鼠标 **拖不动** |
| `selecto` | 61 KB / 19 KB | 2023-12-03 | 只有拖框多选 |

## 决定

用 `subjx`（MIT，零依赖，UMD）。

- 它是唯一同时满足「拖 + 缩放 + 旋转 + 对齐」「仍在维护（当天发版）」「体积最小」「真机验证能读到值」的库。
- **必须同时加载 `dist/style/subjx.css`**（2 KB），否则手柄是 0×0 元素、鼠标点不到。
- 用法是 `subjx(el).drag({ resizable: true, rotatable: true })`；**没有** `x.resize()` / `x.rotate()` 方法。
- 吸附自己补：`subjx` 只提供 `applyAlignment('tr')`（按一下对齐到某方位），**没有拖动时的自动吸附线**。

## 后果

- 引入一个第三方依赖（个人项目，非大厂维护）。体积可接受（gzip 34 KB）。
- 吸附逻辑自己写：用 `getBoundingClientRect()` 比对邻近元素边缘与容器中线，接近阈值时改写 `dx/dy`，并画辅助线。
- 不改目标站点的业务行为：拖动时实时预览（改 style），松手时记下「旧值 → 新值」再把 style 还原。
