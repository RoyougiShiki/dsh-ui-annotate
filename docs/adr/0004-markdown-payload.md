# ADR-0004：条目序列化成结构化 markdown

- **Status**: accepted
- **Date**: 2026-11-13

## 背景

条目最终要进模型。三种候选：纯文本句子、结构化 markdown、JSON。

- 纯句子：模型得猜是哪个元素（「那个按钮」在整页里有几十个）。
- JSON：人读起来痛苦，而这段文字是给用户看的草稿。
- 既有 `dsh-annotated-browser` 和 `dsh-annotated-browser` 的同类都用结构化 markdown，说明它适合输入框。

## 决定

每条标注序列化成一段 markdown，含：

1. 目标元素的**选择器**（`#id` / `data-testid` / 回溯 CSS 路径）与可见文本；
2. **变换**（如果有）：旧值 → 新值，尺寸用相对量 + 参照物表达（「和旁边那张卡一样宽」），位置用「放到 X 之前/之后」；
3. 用户写的**说明**原文。

多条条目按点选顺序拼成一段，一次性写进草稿。

## 后果

- 用户能在草稿里看到自己将发给模型的东西，可以改。
- 序列化逻辑是扩展侧的纯函数，可单测。
